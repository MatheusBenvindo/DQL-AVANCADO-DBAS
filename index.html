Pipeline de Extração, Transformação e Carga (ETL)

Em ambientes de análise de dados analíticos (OLAP / DW), a carga massiva de tabelas staging brutas para tabelas dimensionais e de fatos é frequentemente executada através de consultas atômicas com INSERT INTO ... SELECT, aplicando sanitização de valores nulos, junções (LEFT/RIGHT/INNER JOIN) e normalização categórica com CASE WHEN.

INNER JOIN

Garante integridade referencial mantendo apenas pares válidos entre Staging e Dimensões.

LEFT JOIN

Preserva a integridade da tabela de origem, permitindo capturar entidades sem transações associadas.

RIGHT JOIN

Assegura a inclusão integral da tabela destino/mestre, identificando registros órfãos à esquerda.

CASE WHEN

Aplica regras de negócio, categorizações dinâmicas e substituição condicional de nulos durante a projeção.

INSERT INTO ... SELECT

Executa a migração e carga de alta velocidade direto no MySQL sem sobrecarga de cursores linha a linha.

Arquitetura Técnica de Processamento ETL no MySQL Workbench

O processo de ETL (Extract, Transform, Load) em bancos relacionais consiste em extrair dados operacionais (OLTP) ou arquivos estruturados (CSV/JSON), persistir provisoriamente em uma Staging Area e transformar via consultas SQL para alimentar o Data Warehouse.

FLUXO ATÔMICO DE CARGA ETL
1. EXTRACT (STAGING)

Tabelas `stg_*` brutas recebem dados sem restrição de integridade estrangeira.

2. TRANSFORM (DQL)

Cruzamentos com `JOINs`, saneamento de nulos com `COALESCE` e `CASE WHEN`.

3. LOAD (DW FACT/DIM)

Gravação em lote com `INSERT INTO dw_* SELECT ...` direto no destino.

Exemplo Canônico no MySQL:

INSERT INTO dw_faturamento (cliente_id, nome, valor_total, categoria)
SELECT 
    c.id, 
    c.nome, 
    COALESCE(p.valor, 0),
    CASE 
        WHEN p.valor IS NULL THEN 'SEM_FATURAMENTO'
        WHEN p.valor > 10000 THEN 'CLIENTE_PREMIUM'
        ELSE 'CLIENTE_REGULAR'
    END
FROM stg_clientes c
LEFT JOIN stg_pedidos p ON c.id = p.cliente_id;
